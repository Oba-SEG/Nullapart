## 2. Intended use

Low-latency inline threat **evidence** for the Nullapart policy layer
(`ml_threat_classification` family): per-class scores/threat bands become
`SecurityFinding` evidence that policy evaluates. Failures, model absence
or version mismatch must surface as explicit `Unknown`/`Error` evidence —
never as `CLEAN` (plan decisions 3–5).

Out of scope: autonomous disposition, quarantine decisions without policy,
any customer-facing claim of certification, any use as the sole gate on a
message.

## 3. Training data

Permissive-only public corpora + Nullapart-owned synthetic fixtures
(owner ruling, plan decision 15; full manifest, licenses, exclusions and
checksums in `DATASET.md`). **No customer or production message data ever
enters training.** Copyleft/ShareAlike/unlicensed sources excluded.

Real sources: MeAJOR (Zenodo, CC-BY-4.0), angelfonsecar compilation (MIT),
zero-day phishing (Kaggle, CC0), SPAM+Genuine (Kaggle, Apache-2.0),
zenodo.15235123 (CC-BY-4.0, Malware/Scareware/Baiting/Pretexting seeds).

### Synthetic fixtures — disclosed (plan decision 16)

Generated by `synthetic_fixtures.py` (deterministic, seed 42,
`--per-class 1200`, template-composed, Nullapart-owned, no customer
content): **12,000 fixture rows** across the 10 fixture classes.
Label counts (multi-label rows counted per label):
`AuthFailure 1788`, `SuspiciousContent 1531`, and `1200` each for
`BusinessEmailCompromise`, `CredentialHarvest`, `MaliciousAttachment`,
`MaliciousUrl`, `PolicyViolation`, `Reputation`, `Spoofing`, `Unknown`.

- **8 classes supplied *entirely* by synthetic fixtures** (no permissive
  real source exists): `CredentialHarvest`, `MaliciousUrl`, `Spoofing`,
  `AuthFailure`, `MaliciousAttachment`, `PolicyViolation`, `Reputation`,
  `Unknown`. Their test metrics measure generalization over synthetic
  template families, **not** over production-observed instances of those
  threats.
- **2 classes augmented over small real seeds:** `BusinessEmailCompromise`
  (real seed: Pretexting rows, 78) and `SuspiciousContent` (real seed:
  Scareware rows, 100).
- Real-seed classes: `Malware` (624-row source, mapping table in
  `DATASET.md`), `Phishing`, `Spam`.

Fixture uniqueness enforced at generation (unique-text ratio 1.0 ≥ 0.98
floor); fixtures pass through the same global dedup as real rows.

## 7. Honest limitations

- **Target (c) missed:** +0.0155 < +0.02 macro-F1 over the baseline.
  The deterministic baseline is already strong (0.9652) largely because
  the synthetic-supplied classes are template-consistent for *any*
  learner; both models sit near ceiling on 10 of 13 classes, so the
  remaining headroom concentrates in Phishing/Spam/Malware/SuspiciousContent.
  **This target is reported as failed, not redefined.**
- **Synthetic external validity:** for the 8 synthetic-only classes the
  test set is drawn from the same generator families as training. Scores
  measure internal consistency; real-world precision on those threat
  types is unmeasured until production feedback exists (increment 6 —
  candidates only, never auto-retraining).
- **SuspiciousContent precision 0.7209:** predicts 258 vs support 186 —
  over-predicts. Expect false positives in this band; policy must treat
  the score as evidence, not verdict.
- **Malware support is 8 test rows:** F1/AUC are statistically fragile;
  one mistake moves F1 by >0.1.
- **Clean FPR is threshold-union based:** per-class thresholds were tuned
  on validation for the ≤1% constraint; test FPR 0.0042 confirms no
  overfit to validation, but thresholds are data-dependent and must be
  re-validated if training data changes.
- **Latency:** the ≤50 ms p95 target holds for the int8 ONNX path, which
  is the only intended deployment path; the fp32 torch-eager evaluation
  path (70.76 ms p95) is an offline measurement harness, not the runtime.
- No customer-data evaluation, no external benchmark, no certification
  claim — local harness evidence only (plan "Not claimed" section).
