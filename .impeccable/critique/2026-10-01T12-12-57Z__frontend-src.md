## Anti-Patterns Verdict

**Start here. Does this look AI-generated? Mostly clean, with one real template tell.**

**LLM assessment**: The build passes the absolute bans — no side-stripes, no gradient text, no glassmorphism, no 01/02/03 scaffolding, no eyebrow-over-every-heading, no 32px+ card rounding, and the border+shadow pairs are deliberate hairline + ≤8px neumorphic depth per docs/12, not ghost-card decoration. Second-order reflex is avoided too: it is not cream SaaS admin, and midnight + acid lime is a chosen identity. The remaining tell is the **hero-metric tile row repeated on three pages** — Dashboard (4 identical rounded tiles: icon chip / big number / small label), Operations (same tiles, icons dropped), Scanner operations (same tiles again, plus a ragged orphan fifth tile) — plus the symmetric two-panel grid beneath. A Linear/Stripe-fluent user would largely trust this: familiar shell, semantic pills, real focus rings, no gimmicks. They would pause at raw enum copy, an entirely empty Settings page, tables with no counts/sort/pagination, and rows that don't react to hover.

**Deterministic scan**: The CLI detector is clean — exit 0, **0 findings across 77 files** (42 tsx, 20 css, 15 ts), verified functional with a control probe (a planted `border-l-8` snippet was caught with exit 2), plus targeted re-runs on pages/components/styles and `--gpt --gemini` provider tells, all `[]`. Browser overlay (live-server port 8400) could not inject through the strict CSP (`script-src 'self'` blocked `http://localhost:8400/detect.js` — expected, CSP is owner-ruled off-limits), so evidence used the CDP `setBypassCSP` path: **53 findings across 5 pages** (`/` 8, `/quarantine` 6, `/customers` 16, `/policies` 12, `/audit-log` 8). After code-context review, the vast majority are **false positives against documented design decisions**:
- `gpt-thin-border-wide-shadow` ×5 and `dark-glow` ×7 → the owner-ruled neumorphic token system (`--shadow-lg/glow-lime`, hairline `--color-border`, docs/12 guardrails).
- `ai-color-palette` cyan ×24 → documented semantic status tokens (`--color-success #00f5d4`, severity pills) and icon `svg/path` elements that have no text.
- `text-overflow` ×5 → the standard `.sr-only` visually-hidden pattern (global.css:236-244).
- `cramped-padding` ×4 → intentionally zero-padded scroll wrappers with cell inset from `td` padding.
- `single-font`/`overused-font` ×6 → Inter dominates text; mono stack renders IDs/hashes/timestamps but display/body separation is thin (weakest call — partially real).
- **Real, minor**: `line-length` ×2 — `customers-subtitle` / `audit-subtitle` run ~142-143 chars/line.

## Overall Impression
The console has a real identity and disciplined status semantics — the shell, pills, focus rings and empty states read as designed, not generated. What doesn't work is the last mile of operator UX: three pages repeat the same hero-tile template, machine enums are the primary copy, Settings is an empty nav destination, and the audited release action has two disagreeing entrances. Single biggest opportunity: make the quarantine release path and the dashboard's decision-critical numbers the unmistakable focal points, and stop letting tokens and templates speak where operators need sentences.

## What's Working
1. **Status semantics are genuinely disciplined.** Icon chip + label + color everywhere (critical/high pills with icons, `MANDATORY`/`KILL SWITCH`, `ALLOW`/`QUARANTINE`), never color alone; measured contrast holds in both themes (light lime ink 6.78:1, body 8.82:1; audit TOTAL_FAILS 0).
2. **Interaction-state fundamentals are above average.** 2px lime focus ring on every element tabbed (logo, 11 nav links, buttons, inputs); native `:modal` dialogs with Esc-to-close; disabled-until-valid primary with `aria-describedby` hint; `aria-busy` loading buttons; `role="status"` loading copy; toast stack with `aria-live`.
3. **Empty states teach rather than shrug** — Operations "Nodes appear here once the running stack registers them…", Messages "Enter a query to list matching messages", security posture stated in-context (exports audited + step-up, raw MIME never rendered).

## Priority Issues

- **[P1] What**: Narrow-width nav strands the active item off-screen. At 820px the nav is a nowrap horizontal row (scrollWidth 1310 vs client 796); after navigating to Settings the active pill sits at x=1213-1322 with scrollLeft 0 — no edge fade, no visible scrollbar, no scroll-into-view.
  **Why it matters**: On tablet/laptop widths the operator loses "where am I" entirely and 5 of 11 destinations are invisible until they guess to scroll sideways — worst case for keyboard/zoom users.
  **Fix**: `scrollIntoView({inline:"center"})` on route change + edge-fade/scrollbar affordance; below 640px collapse to a wrapped/grouped menu instead of an infinite strip.
  **Suggested command**: `$impeccable layout`

- **[P1] What**: Settings is an empty page — a single `<h1>Settings</h1>`, nothing else (131 chars of text, zero buttons, no empty state).
  **Why it matters**: A dead nav destination is the fastest way to make the trustworthy numbers next to it look untrustworthy.
  **Fix**: ship the real settings (theme, deployment/context, session) or remove the nav item; if role-gated, render a permission-aware empty state that says what would appear here and for whom.
  **Suggested command**: `$impeccable clarify`

- **[P1] What**: Release affordance is inconsistent and buried. List row = neutral outline "Release" (easy to fat-finger); detail = pink "Release message" placed after ~2000px of scrolling below the fold at 1440×900; both open the same reason-gated confirm.
  **Why it matters**: An audited, effectively irreversible action should have one severity-coded appearance and be reachable without a hunt; today the list over-permits and the detail under-exposes.
  **Fix**: one danger-coded button in both places, sticky detail action bar carrying case ID + severity so context survives the confirm, keep the reason gate.
  **Suggested command**: `$impeccable harden`

- **[P2] What**: Machine tokens are the primary copy — `QUARANTINE_MALWARE` as the "Reason" value, `audit_access_list` as the action, `platform scope` under resource, "RELEASED → Active", `Published by 32e35eba-…`, root hash wrapping mid-string, "Reload" (dashboard) beside "Refresh" (operations).
  **Why it matters**: Operators must translate before they can act; contradictory labels read as bugs.
  **Fix**: human sentence as the value, mono token as a secondary line; distinct verbs for the two refresh actions; never a bare UUID where a name exists.
  **Suggested command**: `$impeccable clarify`

- **[P2] What**: Visual system drift — identical hero-metric tiles on Dashboard, Operations and Scanner operations (with a ragged orphan fifth tile), and an indigo `INBOUND` badge despite DESIGN.md:49 ("There is no blue in the board palette").
  **Why it matters**: The one template tell that makes the console look generated; a sixth color outside the lime/pink/amber/cyan scale quietly breaks "status is readable at a glance".
  **Fix**: vary the treatment — one dominant stat strip (quarantined/threats weighted, drill-down links) instead of four equal cards; scanner tiles to a 3+2 or inline stat list; replace indigo with a neutral/lime-tint direction chip.
  **Suggested command**: `$impeccable colorize`
